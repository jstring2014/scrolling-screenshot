# 整页长截图插件 (Full Page Screenshot)

把当前网页从头到尾截成**一张完整的长图**，自动保存到下载目录。

## 安装

1. 打开 Chrome（或 Edge），地址栏输入 `chrome://extensions`
2. 打开右上角的 **开发者模式 (Developer mode)**
3. 点击 **加载已解压的扩展程序 (Load unpacked)**
4. 选择本文件夹 `jiepingchajian`

## 使用

1. 打开任意想截图的网页
2. 点击工具栏上的蓝色截图图标（或按快捷键 **Alt+Shift+S**）
3. 选择图片格式（PNG 更清晰；JPEG 适合超长页面，体积更小）
4. 点击 **开始截图**
5. 插件会自动从页面顶部滚动到底部，逐屏截取并合成长图，完成后保存到下载目录，并在弹窗里显示预览

截图过程中可随时点击 **取消**；完成后可 **打开预览**（在新标签页查看、缩放或下载长图，多张会依次显示），或 **再截一次**。

## 特性

- **取消**：长页面截图中途可随时停止
- **懒加载支持**：不是靠固定延时"猜"，而是真正等待。截图前先整页预滚动一遍触发懒加载；截每一屏前会**等待当前视口内的图片真正加载完成**（带超时上限），再等字体就绪和一帧绘制，最后才截图，避免截到还没渲染出来的空白
- **页面内滚动容器支持**：自动识别 ChatGPT、后台系统、Web App 等页面里的主滚动区域；当页面本身不滚动时，会滚动并拼接该内容区域
- **超长页面自动分段**：拼接高度超过画布上限（约 32000px）时自动拆成多张图片（part1、part2…），不会失败
- **格式可选**：PNG / JPEG
- **暗色模式**：弹窗自动跟随系统深浅色
- **结果预览 + 快捷键 (Alt+Shift+S)**
- **清晰图标**：图标使用截图框、长页面和向下箭头组合，16/48/128px 均由同一脚本生成
- **进度反馈**：弹窗显示当前阶段、百分比和预计剩余时间
- **预览工具栏**：预览页支持适应宽度、原始尺寸和重新下载
- **隐藏滚动条**：截图时临时隐藏页面滚动条，长图右侧不会出现灰色竖条，结束后恢复
- **固定元素控制**：默认隐藏后续屏幕中的 fixed/sticky 页头页脚，避免重复；遇到表格粘性表头或侧栏被隐藏时，可在弹窗里关闭
- **任务安全**：同一时间只允许一个截图任务；截图中关闭弹窗会自动停止任务（不会留下"孤儿"任务继续滚动/下载）；任意阶段出错都会把页面恢复原状
- **标签页保护**：截图期间切到其他标签页时任务会暂停而不是失败，切回来自动继续（最多等 1 分钟），不会滚动原页面却截到新标签页
- **滚动看门狗**：滚动位置不再推进时立即停止，不会在识别错滚动区时静默产出几十张相同的图
- **多语言**：界面、状态和错误提示全部走 `chrome.i18n`，默认英文，中文（zh_CN）已完整翻译
- **最小权限**：仅使用 `activeTab`、`scripting`、`downloads`，不申请 `<all_urls>` 常驻权限
- **低内存拼接**：拼接阶段逐屏解码、画完即释放，完成后释放中间截图，避免结果长期驻留后台内存
- **预览缓存**：最近一次截图结果保存到扩展 IndexedDB，预览页不依赖 service worker 的临时内存
- **无缝拼接**：兼容小数缩放（Windows 125%/150%，`devicePixelRatio`=1.25/1.5），屏与屏之间不会出现 1px 透明/白色细线
- 文件名自动使用网站域名 + 时间戳

## 工作原理

- `popup.html / popup.js` — 弹窗界面，显示格式选择、截图选项、阶段进度和结果预览
- `viewer.html / viewer.js` — 新标签页预览，支持缩放和下载缓存图片
- `background.js` — 核心逻辑：
  - 注入页面识别 `window` 或主滚动容器，读取尺寸、关闭平滑滚动
  - 逐屏滚动页面或内容容器 + `chrome.tabs.captureVisibleTab` 截图（自动处理截图频率限制）
  - 对页面内滚动容器进行裁剪拼接，避免侧栏/空白区域重复进入长图
  - 滚动时隐藏 `fixed/sticky` 元素，避免页头/页脚重复出现
  - 用 `OffscreenCanvas` 把各屏拼接成一整张 PNG
  - 通过 `chrome.downloads` 保存，把最近一次结果写入 IndexedDB，并恢复页面原始状态

## 说明与限制

- 浏览器内置页面（`chrome://`、扩展页面等）无法截图。
- 懒加载：插件会等待视口内图片加载完成（单屏最长等待 `MAX_RENDER_WAIT_MS`，默认 1500ms）。若站点特别慢，可调大该值。
- **虚拟列表 / 无限滚动的固有限制**：像 `react-window`、`content-visibility:auto` 这类技术，**屏幕外的内容根本不在 DOM 里**（滚走后又被销毁），这种"滚动截图+拼接"的方式无法截全，任何同类插件都受此限制。对这类页面只能截到滚动过程中存在过的部分。
- 页面内有多个可滚动区域时，插件会自动选择面积和可滚动距离最大的主区域；少数复杂布局可能需要先把鼠标滚轮能滚动的区域停在目标内容上再截图。
- 拼接画布同时受最长边（32000px）和总像素面积（1 亿像素）两个上限约束，超过时自动拆分为多张（part1、part2…）。高分屏上宽度越大，单张能容纳的高度越小。
- 为防无限滚动页面失控，单次最多截取 `MAX_SCREENS`（默认 80）屏；超过时弹窗会明确提示已截取前多少屏。

## 测试

```bash
npm test
```

该命令分两步：

1. `npm run check` — JS 语法检查 + `tools/validate-extension.mjs`，校验 `manifest.json`、入口文件、图标尺寸、权限配置、`manifest` 与 `package.json` 版本一致，以及全部 i18n 约束（各 locale key 集合一致、无空文案、占位符跨语言一致、代码里没有遗漏的硬编码中文、引用的 message key 都存在）。
2. `npm run test:e2e` — 真实浏览器端到端截图测试，见下。

重新生成扩展图标：

```bash
npm run icons
```

图标源文件在 `icons/source.svg`，PNG 输出为 `icons/icon16.png`、`icons/icon48.png`、`icons/icon128.png`。

生成 Edge 商店素材：

```bash
npm run store-assets
```

输出目录为 `store-assets/`，包含 300x300 logo、1280x800 截图和推广图。

生成 Edge 上传包：

```bash
npm run package
```

上传包输出到 `dist/edge-full-page-screenshot-版本号.zip`，只包含扩展运行所需文件。完整发布前可运行：

```bash
npm run release
```

上架材料：
- `PRIVACY.md`：隐私政策，可发布到网页后把 URL 填入 Partner Center。
- `STORE_LISTING.md`：商店描述、权限说明、数据披露和认证测试说明，可直接复制到 Partner Center。

`tools/e2e-capture.mjs` 会在真实 Chromium 里加载解包扩展，对一个色带固定的测试页跑完整流程（滚动 → 逐屏截图 → 拼接 → 下载 → 写 IndexedDB），然后逐像素校验结果：

- 拼接总高等于「每屏高度 × 屏数」（允许每屏 1px 舍入）；
- 每条色带都落在自己的纵向偏移上、互不重复（顺序和偏移都正确）；
- 缓存到 IndexedDB 的是 `image/png` 的 Blob 而不是 base64 字符串；
- 分段数量符合面积上限推导的结果，且每段都在画布预算内；
- `position: fixed` 页头只出现一次，没有随每屏重复；
- 发给弹窗的每条状态/错误消息都带 message key，没有硬编码文案；
- 顺带报告耗时，用来判断是否逼近 MV3 对单次事件 5 分钟的硬限制。

实测数据（1000×700 窗口、DPR 2）：**80 屏耗时约 90 秒**（约 1.1 秒/屏），service worker 全程存活，距离 300 秒上限还有较大余量；输出为 4 段、总高 98080px。

该测试需要本机有 Chromium：优先用 `CHROME_BIN`，否则自动在 Playwright 缓存和 `/Applications` 里找；都找不到时会跳过而不是失败。

```bash
npm run test:e2e
```

改屏数：`E2E_SCREENS=80 npm run test:e2e`
